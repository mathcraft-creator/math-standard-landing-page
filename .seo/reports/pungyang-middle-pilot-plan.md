## 1. 목표와 범위

첫 학교 SEO 파일럿은 `풍양중 수학`을 중심으로 학교 시험 정보를 찾는 학생·학부모에게 실제 시험 자료와 학원의 분석 방법을 제공하고, 필요한 경우 중·고등 과정 안내와 상담으로 연결하는 상시 허브를 설계하는 작업이다.

이번 단계에는 문서 설계만 포함한다. 학교 페이지 생성, 기존 HTML·CSS·JavaScript 수정, sitemap·`llms.txt` 변경, 구조화 데이터 삽입, CTA 변경, 배포는 하지 않는다.

## 4. URL 결정

권고 URL은 `/schools/pungyang-middle/`이다.

| 후보 | 평가 |
| --- | --- |
| `/schools/pungyang-middle/` | 학교 허브라는 계층이 분명하고 시험별 하위 문서를 확장하기 좋음. 연도와 무관하게 유지 가능 |
| `/pungyang-middle.html` | 현재의 평면 HTML 구조와 비슷하지만 학교·시험 계층 확장이 어렵고 URL 의미가 약함 |
| `/schools/pungyang-middle.html` | 학교 분류는 드러나지만 디렉터리형 허브와 하위 문서 관계가 덜 자연스러움 |

현재 정적 배포 설정에서 이 URL을 구현하려면 향후 `schools/pungyang-middle/index.html`을 만들고 `.vercelignore`가 `schools` 디렉터리를 배포하도록 조정해야 한다. 구현 단계의 합격 조건은 다음과 같다.

- `/schools/pungyang-middle/`이 HTTP 200과 HTML로 응답한다.
- 슬래시 없는 경로의 응답 또는 리디렉션을 확인하고 canonical은 슬래시 있는 대표 URL로 통일한다.
- 존재하지 않는 학교·시험 경로가 홈 콘텐츠와 200으로 응답하지 않고 실제 404를 유지한다.

## 6. 권장 정보 구조

1. **Hero**
   - H1과 한 문장 설명
   - 학교 공식 사이트나 제휴 페이지가 아니라 학원의 분석·대비 안내임을 분명히 한다.

   - 실제 시험지에서 확인하는 항목과 준비 순서를 2~4문장으로 답한다.

   - 총 문항 수, 객관식·서술형, 단원·유형을 원자료가 있을 때만 표로 제공한다.

   - 관찰 사실, 계산 데이터, 학원 분석을 구분한다.

7. **시험 대비 방식**
   - 학교별 시험 분석, 서술형 연습, 오답 재풀이, 재테스트 등 현재 중·고등 과정에서 확인되는 방법을 설명한다.
8. **시험별 상세 분석**
   - 충분한 실제 데이터가 있을 때만 하위 문서로 연결한다.
9. **FAQ**
   - 실제 페이지 내용으로 답할 수 있는 질문만 싣는다.
10. **출처와 분석 방법**
    - 원자료, 검수, 계산, 난이도 기준, 갱신일을 설명한다.
11. **과정·상담 CTA**
    - 중·고등 과정 안내와 상담 신청으로 연결한다.

- **H1 보조 후보:** `풍양중 수학 시험 분석과 내신 대비`

자료를 아직 확보하지 못한 상태에서 위 문구를 운영 페이지에 게시하지 않는다. `실제 시험지 기반`이라는 표현은 출처·검수 요건이 충족된 뒤에만 사용한다.

이 블록은 특정 학년이나 시험의 사실을 임의로 주장하지 않는다. 실제 자료가 준비되면 바로 아래에 자료 범위와 핵심 관찰 사실을 연결한다.

## 9. 필요한 데이터 모델

한 시험을 분석 단위로 삼고, 문항별 기록을 집계의 원천으로 유지한다.

최소 데이터 계약은 다음 필드명을 유지한다.

```text
school
year
grade
semester
examType
totalQuestions
objectiveQuestions
subjectiveQuestions
units
questionTypes
difficulty
analysisMethod
analysisDate
```

| 분류 | 필드 예시 | 규칙 |
| --- | --- | --- |
| 시험 식별 | `schoolName`, `year`, `grade`, `semester`, `examType`, `examDate` | 원자료에서 확인되는 값만 저장 |
| 원자료 | `sourceDocumentId`, `sourcePath`, `sourceType`, `acquiredAt` | 공개 파일과 내부 원본을 구분 |
| 검수 | `ocrStatus`, `reviewer`, `reviewedAt`, `verificationStatus` | OCR만으로 확정하지 않음 |
| 문항 | `questionNumber`, `format`, `unit`, `topic`, `points` | 배점이 없으면 비워 둠 |
| 집계 | `totalQuestions`, `objectiveQuestions`, `subjectiveQuestions`, `unitCounts` | 문항 행에서 계산하고 산식 기록 |
| 분석 | `questionType`, `difficultyRating`, `difficultyCriteria`, `analysisNotes` | 학원 해석임을 표시 |
| 공개 | `publicationPermission`, `redactionStatus`, `publicExcerpt` | 개인정보·저작권 확인 후 공개 |
| 변경 | `analysisDate`, `modifiedAt`, `changeReason` | 수정 이력 유지 |

페이지 출력에서는 필드를 다음처럼 구분한다.

- **Observed Fact(관찰 사실):** 시험 식별, 문항 형식, 단원, 배점 등 원자료에서 직접 확인한 값
- **Calculated Data(계산 데이터):** 문항 수와 배점에서 산출한 분포
- **Academy Analysis(학원 분석):** 난이도와 준비 우선순위

난이도 판단은 단순 사실처럼 쓰지 않는다. 예를 들어 `수학의 기준 자체 분석 기준 고난도 4문항`처럼 판단 주체, 기준, 결과가 함께 드러나게 하고 바로 옆에 난이도 기준과 분석일을 연결한다.

## 10. 현재 확보된 정보

사용자가 제공한 JSON과 DOCX를 검토해 첫 시험의 구조화 데이터가 확보됐다. 상세 결과와 불일치는 [풍양중 3학년 2026학년도 1학기 기말고사 자료 검토](./pungyang-middle-source-review.md)에 기록한다.

- 시험 식별: 풍양중학교 3학년, 2026학년도 1학기 2차 정기시험·기말고사, 수학
- 시험 구성: 총 21문항 100점, 선택형 17문항 80점, 논술형 4문항 20점
- 대단원 집계: 이차방정식 9문항 40점, 인수분해 5문항 26점, 통계 7문항 34점
- JSON의 모든 문항에 번호·본문·배점을 페이지 이미지와 대조했다는 검증 플래그가 있다.
- DOCX에는 문항별 단원·난이도와 학원의 시험 대비 제안이 있다.
- 기존 사이트에는 학교별 시험 분석, 시성비, 서술형, 오답 재풀이, 재테스트 방식과 학원 NAP가 있다.

난이도는 JSON의 관찰 필드가 아니라 DOCX의 `Academy Analysis`다. 문항별 표는 하 5·중 10·상 6문항이지만 DOCX 본문은 하 4·중 11·상 6문항으로 달라 공개 전 정정해야 한다.

## 11. 아직 필요한 실제 자료와 확인

- JSON이 참조하는 원본 시험지 PDF 또는 검증 가능한 페이지 이미지
- 시험지·문항 원문·이미지의 공개 권한과 개인정보 삭제 기준
- 난이도 하·중·상의 정의, 판정 기준, 최종 검수자
- DOCX 난이도 문항 수 불일치 정정
- JSON과 DOCX의 교육과정 코드 매핑 기준
- 분석 작성자·검수자와 공개용 분석일
- 추세를 다루기 위한 같은 학교의 비교 가능한 시험 최소 두 건

현재 데이터로 문항 수·배점·대단원 분포를 근거 있게 설계할 수 있다. 다만 원본 재대조와 공개 검수가 끝나기 전에는 페이지를 배포하거나 난이도·최근 경향을 관찰 사실처럼 표현하지 않는다.

## 12. 구조화 데이터 설계

초기 허브에서 검토할 유형은 다음과 같다.

- `WebPage`: 페이지 URL, 이름, 설명, 언어, 수정일을 실제 화면과 일치시킨다.
- `BreadcrumbList`: 화면에 `홈 > 중·고등 > 풍양중 수학` 탐색 경로가 있을 때 같은 순서로 제공한다.
- `FAQPage`: FAQ가 화면에 그대로 보이고 질문·답변이 JSON-LD와 정확히 일치할 때만 추가한다.
- `EducationalOrganization` 참조: 기존 학원 엔터티 `/#academy`와 중·고등 브랜드 `/#secondary-academy`의 현재 타입·관계를 재사용하고, 학교 엔터티와 혼동시키지 않는다.

풍양중을 학원 소유 조직, 지점, 공식 파트너로 표현하지 않는다. 시험별 하위 분석 문서가 실제로 작성되면 `Article`을 검토하되 작성자, 게시일, 수정일, 출처는 실제 값만 사용한다. 구조화 데이터가 검색결과 확장 노출을 보장한다고 설명하지 않는다.

## 14. sitemap과 `llms.txt` 향후 반영

현재 파일은 수정하지 않는다. 페이지 구현, 검수, 사용자 승인, 운영 배포가 끝났을 때 다음을 수행한다.

- `sitemap.xml`에 `https://math-standard-landing-page.vercel.app/schools/pungyang-middle/`을 한 번만 추가한다.
- `lastmod`는 실제 공개 또는 실질적 수정일을 사용한다.
- 시험별 하위 문서는 실제 공개된 문서만 추가한다.
- `llms.txt`에는 실질적인 출처 기반 분석이 있을 때 학교 분석 섹션을 추가한다.
- 제안 설명: `풍양중 수학 시험 자료와 내신 대비 방식: /schools/pungyang-middle/`
- canonical, sitemap, 내부 링크, `llms.txt`의 URL 표기가 모두 같은지 검증한다.

## 15. CTA 전략

CTA는 페이지의 정보 가치를 확인한 뒤 선택할 수 있게 둔다.

- 분석 요약 뒤: 중·고등 과정 안내로 연결하는 보조 CTA 1개
- 페이지 하단: 상담 신청 CTA 1개
- 시험 상세 문서: 학교 허브 또는 과정 안내로 먼저 연결하고 상담 CTA를 반복하지 않는다.

권장 본문 방향은 `현재 학습 상태와 시험 준비 방향을 먼저 확인해보세요.`이다. 버튼은 `풍양중 시험 자료를 바탕으로 학습 상담 받기`처럼 근거와 행동을 연결하되, 실제 분석 자료가 준비된 이후에만 사용한다. `공식`, `지정`, `완벽 대비`, `적중 보장` 표현은 사용하지 않는다.

FAQ 후보는 실제 학원 운영 방식과 확보된 시험 자료로 답할 수 있을 때만 사용한다.

- 풍양중 수학 시험은 어떻게 준비하나요?
- 시험 대비는 언제부터 시작하나요?
- 서술형은 어떻게 대비하나요?
- 틀린 문제는 어떻게 관리하나요?
- 풍양중 학생은 개별진도로 수업하나요?

## 16. 성공 지표

현재 값은 [검색 베이스라인](./search-baseline.md)과 같이 `Not measured yet`이다. 공개 후 다음 순서로 본다.

| 구분 | 지표 | 판단 목적 |
| --- | --- | --- |
| 발견 | sitemap 처리, 크롤링 시점 | 검색엔진이 URL을 발견했는지 확인 |
| 색인 | Google·네이버 색인 상태, 선택 canonical | 기술적 공개 성공 확인 |
| 검색 | 대상 검색어 노출, 클릭, CTR, 평균 게재순위 | 검색 의도와 페이지 연결 확인 |
| 랜딩 | 검색어별 랜딩 URL | 허브와 기존 중·고등 페이지의 의도 중복 확인 |
| 참여 | 참여 시간 또는 스크롤 등 도입된 분석 도구가 제공하는 지표 | 분석 내용을 실제로 읽는지 확인 |
| 탐색 | 과정 안내·시험 상세 내부 링크 클릭 | 사용자가 다음 정보를 찾는지 확인 |
| 전환 | 상담 CTA 클릭·완료 | 측정 도구가 있을 때만 기록 |
| 상담 | 실제 상담 유입과 유입 경로 | 운영 기록으로 확인할 수 있을 때 검색 유입과 연결 |
| 품질 | 원자료 정정 건수, 오래된 분석 비율 | 데이터 운영 품질 확인 |

노출이나 순위의 목표 숫자는 과거 데이터 없이 임의로 정하지 않는다. T0, 공개 후 14일, 28일, 분기 단위로 같은 조건의 데이터를 비교한다.

## 17. 구현 전 결정 사항

사용자 승인과 함께 다음 입력이 필요하다.

1. 첫 공개에 사용할 실제 시험: 학년도, 학년, 학기, 시험 종류
2. 시험지 또는 분석 원자료의 위치와 공개 가능 범위
3. OCR 사용 여부와 사람 검수 담당
4. 난이도 판정 기준
5. 배점이 없거나 확인되지 않는 문항의 표시 방식
6. 시험지 이미지·문항 발췌의 게시 권한과 개인정보 삭제 기준
7. 한 건의 시험으로 허브를 먼저 공개할지, 두 건을 확보해 비교까지 할지
8. 페이지가 학교의 공식 채널이 아니라는 표현의 최종 문구

권고 결정은 `실제 시험 한 건 이상 + 사람 검수 완료 + 공개 권한 확인`을 최소 공개 게이트로 삼고, 두 건 이상 확보되기 전에는 추세 섹션을 만들지 않는 것이다.

## 18. 구현 단계의 작업 단위

사용자가 이 설계를 승인한 뒤에도 한 번에 크게 변경하지 않는다.

1. 실제 시험 자료 정리와 문항 데이터 검수
2. 학교 허브 HTML 초안 작성
3. 로컬 링크·접근성·구조화 데이터 테스트
4. 사용자 콘텐츠 검토
5. 배포 설정, sitemap, `llms.txt` 반영
6. Preview 또는 운영 검증 후 등록 도구에서 URL 확인

각 단계는 수정 후 테스트하고 다음 단계로 넘어간다. 현재 단계에서는 위 작업을 실행하지 않는다.
