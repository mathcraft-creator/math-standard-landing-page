# 학교별 학년·학기 수강과목 추천 사이트 계획

작성: 2026-11-23. 범위: 엑셀 조사와 서비스·데이터·구현 계획. 이번 작업에서는 서비스 구현·배포·엑셀 수정을 하지 않는다.

## 1. 제안하는 서비스

기존 과목·전공 탐색관에 **학교별 과목 선택 설계**를 추가한다. 학생이 학교와 입학연도, 희망학과 또는 진로를 입력하면 그 학교의 편성 자료와 선택 조건에 맞는 6학기 수강 계획을 제안한다. 학생이 과목을 바꾸면 선택 가능 여부·학점·후속 학기 계획을 다시 계산한다.

첫 출시 대상은 자료가 있는 **진접고·오남고·진건고의 2027학년도 입학생**으로 제안한다. 광동고도 학교 목록과 자료 현황에 표시하되, 미확보 코호트의 완성 추천안은 만들지 않는다. 재학생은 자료가 확보된 학기만 확인할 수 있게 하고, 해당 입학연도의 나머지 편제표를 확보한 뒤 전 학기 추천으로 확장한다.

핵심 결과는 ‘전공 관련 과목 목록’이 아니라 **학교지정 과목 + 선택군별 추천 조합 + 추천 이유 + 미확인 조건**이 담긴 학생용 계획표다. 합격 가능성이나 공식 수강신청 결과로 표현하지 않는다.

## 2. 실제 엑셀 조사 결과

`curriculum/`의 엑셀 5개, 총 35개 시트를 읽었다. 원본은 수정하지 않았다. 학교별 파일은 각각 7개 시트이며, 비교 파일도 7개 시트다. 다음은 실제 읽은 `2027입학생_3개년`의 과목 편성 행 수다. 행 수는 고유 과목 수나 한 학생의 수강 과목 수가 아니다.

| 학교 | 1-1 | 1-2 | 2-1 | 2-2 | 3-1 | 3-2 | 편성 행 합계 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 진접고 | 13 | 12 | 21 | 20 | 30 | 26 | 122 |
| 오남고 | 12 | 12 | 20 | 20 | 25 | 22 | 111 |
| 진건고 | 12 | 12 | 21 | 25 | 23 | 19 | 112 |
| 광동고 | 미확보 | 미확보 | 미확보 | 미확보 | 미확보 | 미확보 | 실제 과목 0, 미확보 표시 6행 |

출처 범위:

- 진접고 `2027입학생_3개년!A1:S123`, 오남고 `2027입학생_3개년!A1:S112`, 진건고 `2027입학생_3개년!A1:S113`.
- 광동고 `2027입학생_3개년!A1:S7`, `조사현황!A1:H20`. 광동고 주 시트에는 2025 입학생의 고3 공식 편성 44행, 보조 출처 과목 3행, 자료 미확보 4행이 섞여 있다.
- 비교 파일 `진로계열별 과목 선택 참고!A1:H39`는 일반적 진로 연계 **해석**이고 대학 공식 권장과목이 아니라고 명시한다.
- 비교 파일 `조사 출처 및 미확인 사항!A1:H20`에 자료 부족·출처·차이·편성 변경 가능성이 정리돼 있다.

학교별 주요 데이터 시트에는 학교, 학년·학기, 과목, 학점, 교과군, 적용 학년도, 입학 학년도, 운영 형태, 개설 확인 상태, 출처 URL·문서·확인일, 선택군·선택 조건 등 **19개 열**이 있다. 초기 데이터 모델을 만들기에 유용한 구조다.

### 반드시 구분할 기준

1. 학교명 시트는 **2027년의 고1·고2·고3**을 모은 것으로 2027·2026·2025 입학생이 섞여 있다.
2. `2027입학생_3개년`은 **한 입학연도의 2027~2029년** 계획이다. 개인 6학기 추천은 이 구조를 기준으로 한다.
3. 엑셀의 ‘공식 원문 확인’은 파일 작성자가 기록한 출처 상태다. 이번 조사에서 공식 PDF를 새로 대조한 것은 아니다. 기록상 확인일은 2026-10-30이며, 현재 날짜의 최신 개설 확정으로 바꾸지 않는다.
4. 편제표상 후보, 수강신청 후 개설 확정, 다음 해 편성 계획, 보조 출처 단독 정보, 자료 미확보를 구분한다. 실제 시간표·폐강 여부는 이 엑셀만으로 확정할 수 없다.
5. 학년·학기 후보를 합산해 학생 학점으로 계산하지 않는다. 예를 들어 ‘택4’ 후보 12개는 12개 모두 수강한다는 뜻이 아니다.

학교 공식 게시물 4곳의 링크도 열어 보았으나 웹 도구에서 접근 오류가 발생했다. 따라서 이번 계획은 제공 엑셀 조사에 근거하며 공식 사이트 최신성 검증은 다음 데이터 확인 단계로 남긴다.

## 3. 사용자 이용 흐름

**학교 선택 → 입학연도·시작 학기 → 희망학과/진로 → 이수·선택 상태 → 추천 계획 → 과목 변경·저장** 순서로 구성한다.

| 단계 | 입력·화면 | 설계 기준 |
|---|---|---|
| 학교·입학연도 | 학교 4곳, 지원되는 입학연도, 자료 기준일 | 선택 전 자료 확보 범위를 표시. 미지원 연도 자동 대체 금지 |
| 시작 위치 | 신입생/재학생, 계획 시작 학년·학기 | 지난 학기는 이수 기록으로 잠그고 남은 학기만 추천 |
| 목표 | 희망학과 또는 진로 자유 입력 + 후보 선택 | ‘반도체’, ‘개발자’ 같은 입력을 학과·계열 후보로 연결한 뒤 학생이 확정 |
| 보완 입력 | 이미 이수·확정한 과목, 반드시 듣고 싶은 과목, 제외 과목 | 선택 사항. 모르면 ‘미입력’으로 두고 선이수 충족을 단정하지 않음 |
| 추천 방식 | 전공 연계 우선 / 관심 분야 균형 | 검증된 제약은 동일하게 적용. 임의의 과목 난도 점수는 넣지 않음 |
| 결과 | 6학기 카드, 선택군별 조합, 학점, 추천 이유·대안·확인 사항 | PC는 전체 표, 모바일은 학년별 접이식 카드 |
| 조정·공유 | 추천 과목 바꾸기, 대안 비교, 브라우저 저장·인쇄 | 학생의 수정 내용을 유지하고 충돌을 즉시 설명 |

학과·진로 연결이 모호하면 후보를 보여 주고 선택하게 한다. 예를 들어 ‘의료’라는 말만으로 의학·간호·보건을 하나로 확정하지 않는다. 지원되지 않는 진로는 일반 탐색으로 안내한다.

개인 이름·전화번호·성적을 필수 입력으로 받지 않는다. 첫 버전은 로그인 없이 브라우저에 저장하고, 공유는 인쇄/PDF 저장과 텍스트 복사로 시작한다. 기존 상담 안내 링크는 선택적으로 제공한다.

## 4. 추천 결과의 구성

- 학생 정보: 학교·입학연도·대상 학기·선택한 목표.
- 자료 현황: 기준일, 편성 계획/후보 여부, 자료 누락, 공식·보조 출처 충돌.
- 학기별 학교지정 과목: 임의로 제거하거나 전공에 맞춰 바꾸지 않는다.
- 선택군별 과목: ‘12과목 중 4개’와 현재 선택 개수를 함께 표시한다.
- 추천 이유: 목표와의 관련성, 학교에서 배치 가능한 학기, 이전 학습과의 연결, 근거 자료.
- 대체 후보: 같은 선택군의 대안과 바꿀 때 다른 학기에 미치는 영향.
- 과목 관련성 표: 목표와 연계된 과목 중 계획에 포함된 항목과 빠진 항목. 합격률·공식 적합도 %로 표시하지 않는다.
- 확인 목록: 선이수 미입력, 교차 편성 배정, 학교 개설 미확정, 목표 대학 자료 연도 불일치 등.

학기·학점·선택군은 **학교 편성 사실**, 진로와의 관계는 **추천 해석**, 대학별 권장과목은 **해당 모집연도의 공식 자료**로 각각 표시한다. 화면에서 구현용 데이터 키나 내부 점수를 노출하지 않는다.

### 엑셀에서 확인한 표시 사례

2027 입학생 기준 ‘확률과 통계’는 진접고에서 3학년 1학기 학생 선택이고, 오남고·진건고에서는 같은 학기에 학교지정 과목이다. 따라서 같은 희망학과를 입력해도 ‘새로 선택할 과목’과 ‘이미 포함되는 과목’이 달라야 한다.

진접고는 ‘인공지능 수학’이 해당 편제표에 없고 오남고·진건고에는 2학년 2학기 선택 후보로 있다. 진접고 학생에게 이 과목을 학교 수강 계획에 넣어서는 안 된다. 별도 대체 학습 안내를 검토하더라도 실제 과목 동등성을 단정하지 않는다.

위는 데이터에 따른 동작 예이며 아직 학생별 추천안을 계산한 결과는 아니다.

## 5. 추천 엔진

첫 버전은 **검증 가능한 규칙과 조합 탐색**으로 구현한다. 생성형 AI가 과목·학기·학점을 만들어 내는 구조는 사용하지 않는다.

### 처리 순서

1. 학교 + 입학연도 + 자료 버전을 고정하고 지원 학기와 미확보 범위를 확인한다.
2. 희망학과/진로를 기존 탐색관의 학과·계열에 연결한다. 진로 별칭과 연결 근거는 별도 검수한 표로 관리한다.
3. 학교지정 과목과 이미 이수/선택한 과목을 먼저 배치한다.
4. 학교별 선택군·학점·중복 이수·학기 교차·확인된 선이수 조건을 구조화한다.
5. 목표 연계 과목을 학교 후보와 교차해 후보 조합을 만든다. 선택군을 따로 최적화하고 끝내지 않고 6학기 전체의 연결·중복도 확인한다.
6. 실제 충족해야 하는 조건을 통과한 조합만 진로 연계·학생 선호·근거 수준으로 비교한다. 상위 대안은 최대 3개로 제안한다.
7. 불가능하거나 입력이 부족하면 ‘해당 조건의 완성안 없음’ 또는 ‘추가 확인 필요’를 반환한다. 빈자리를 임의 과목으로 채우지 않는다.
8. 결과의 각 과목에 선택군·원본 셀·추천 근거를 연결한다. 같은 입력과 버전에서는 같은 결과를 반환한다.

### 반드시 지켜야 하는 조건과 참고 조건

| 조건 | 처리 |
|---|---|
| 해당 학교·입학연도·학기 편성 | 다른 학교·연도에서 가져오지 않는 필수 조건 |
| 학교지정 과목·선택 개수·선택군별 학점 | 검증된 규칙은 반드시 충족. 필수 과목의 학점이 불명확하면 완성 계획 판정 보류 |
| 학교가 명시한 선수/동시이수·연계 제한 | 공식 근거가 확인된 항목만 강제 |
| 일반적 권장 이수 순서·분석 메모 | 참고 경고와 우선순위로 적용. 법적/학교 필수 조건으로 승격하지 않음 |
| 진로 연계·흥미·학생 고정 선택 | 유효한 조합 내에서 비교. 학생 선택이 충돌하면 풀어야 할 조건을 설명 |
| 미확보·학점 불명·출처 충돌 | 자동 확정 추천에서 보류. 자료가 없다는 이유로 미개설이라고 표시하지 않음 |

‘택1·학기 교차’는 두 학기에 같은 과목을 중복 권장하지 않고 연간 묶음으로 처리한다. 단, 엑셀에 ‘반별 교차 편성 추정’이라고 적힌 항목은 실제 학기 배정까지 확정하지 않고 ‘반 편성 확인 필요’로 표시한다. 학생이 자유롭게 학기를 옮길 수 있다고 가정하지 않는다.

탐색 방법은 작은 선택군의 후보 조합을 만들고 충돌하는 부분 조합을 일찍 제외하는 방식으로 시작한다. 반복 실행은 Web Worker에서 수행하도록 설계하고 시간 제한을 둔다. 제한에 걸리면 최적이라고 주장하지 않고 확인된 유효안과 탐색 범위를 표시한다.

## 6. 데이터 준비와 검수

### 원천과 파생 데이터

| 원천 | 용도 | 제한 |
|---|---|---|
| 학교별 19열 본표 | 개설 후보·학점·선택군·출처의 기준 | 입학연도/적용연도 혼합 여부 확인 |
| 2027입학생_3개년 | 첫 버전의 6학기 추천 기준 | 후속 학년은 변경 가능한 계획 |
| 비교 파일 | 교차 검수·학교 차이와 진로 연결의 출발점 | 본표보다 우선하지 않음. 해석을 공식 권장으로 변환하지 않음 |
| 수학교과_분석 | 수학 흐름·메모의 검토 자료 | 해석과 공식 제약 분리 |
| 출처_검증기록·조사현황·네이버에듀_대조 | 출처·누락·충돌 관리 | 충돌을 조용히 덮어쓰지 않음 |
| 기존 탐색관 데이터 | 과목 설명·학과·계열 연계 | 학교 편성 정보 및 2030 대입 권장과목으로 간주하지 않음 |

변환 작업은 원본을 읽어 별도 JSON을 만드는 방식으로 하고 엑셀을 수정하지 않는다. 시트별 원본 행 수·누락·매칭 실패·선택군 검증 결과와 파일 해시를 보고서로 남긴다. 학생 브라우저에서 엑셀 5개를 직접 파싱하지 않는다.

필요 데이터:

- `schools`: 학교 ID·표시명.
- `curriculumVersions`: 학교·입학연도·교육과정·대상 연도·자료 상태·검수 버전.
- `offerings`: 원본 과목명·표준 과목 연결·학년·학기·편성 학점·운영 형태·확인 상태·출처 셀.
- `selectionGroups`: 학기별 선택 수·후보·학점 조건·연간 교차 묶음·연계/배제 조건·근거.
- `subjectMappings`: 학교 과목명과 기존 탐색관 과목의 연결, 별칭, 미연결 사유. 숫자 ID만 저장하지 않고 원본 버전도 고정한다.
- `careerMappings`: 진로 표현→학과/계열, 과목 관련성·근거·검수 상태.
- `studyRules`: 권장 이수 순서와 학교 필수 규칙을 구별한 조건.
- `universityRecommendations`: 모집연도·대학·모집단위·근거·확인 상태. 초기 기본 추천과 별도 관리.

‘기술·가정’ 같은 표기 차이, ‘융합사고수학’ 같은 학교 과목, 괄호가 붙은 ‘인공지능 윤리(교)’ 등은 현재 탐색관 명칭과 완전히 같지 않다. 정규화 후보를 자동 제안하되 수동 검토 없이 서로 다른 과목을 합치지 않는다. 학교 과목은 탐색관에 연결되지 않아도 원래 과목으로 유지한다. 모든 후보가 미확인인 선택군은 완료 판정을 보류한다.

재학생 지원을 확장할 때는 2025·2026 입학생의 전 학기 편제표를 별도로 추출한다. 현재 학교명 시트에 있는 2027년 한 학년의 과목을 이어 붙여 한 학생의 3년 계획으로 만들지 않는다.

### 학점 검산

선택 후보 전체 합계가 아니라 학교지정 과목과 선택군에서 실제 고른 과목을 합산한다. 교차 편성은 해당 학기의 실제 1과목만 반영한다. 비교 파일에 기록된 진접고의 학기별 교과 학점은 30/29/30/29/30/29이고 오남고·진건고는 각 학기 29다. 이는 엑셀 대조용 기준이며 현행 졸업요건의 충분조건으로 사용하지 않는다. 창체·교과군별 요건·미이수/전입 이력 등 필요한 정보가 없으면 ‘졸업요건 충족’ 판정을 하지 않는다.

## 7. 대입 자료 연도 처리

일반적인 3년 진학 흐름에서 2027 입학생은 2029년 고3·2030학년도 대입 대상이다. 유급·조기졸업 등 예외는 별도 입력으로 다룬다. 기존 탐색관의 **2028 대입 권장과목을 이 학생에게 현재 적용되는 대학 권장으로 표시하지 않는다**.

첫 버전은 ‘희망전공과의 학습 연계 + 학교에서 선택 가능한 조합’을 중심으로 한다. 대학 목표 입력은 선택 사항으로 두고 대상 모집연도의 검증된 자료가 없으면 해당 대학의 최신 요건 기반 추천을 제공할 수 없다고 표시한다. 예전 자료를 보려면 기준 연도를 명확히 보여 주는 참고 탭으로 분리한다.

## 8. 기술 구조와 기존 서비스 통합

기존 정적 HTML/CSS/JavaScript와 상대 경로를 유지한다. 제안 경로는 `/curriculum/planner/`이며 기존 `/curriculum`의 탐색 기능을 대체하지 않는다. 별도 정적 페이지와 필요한 JSON만 불러와 기존 대용량 탐색관을 먼저 로드하지 않아도 사용 가능하게 한다.

구현 시 예상 파일:

```text
curriculum/planner/index.html
assets/course-planner.css
assets/course-planner.js
assets/course-planner-engine.js
assets/course-planner-worker.js
data/curriculum/schools.json
data/curriculum/subjects.json
data/curriculum/career-mappings.json
data/curriculum/rules.json
data/curriculum/schools/{school-id}/{entry-year}.json
scripts/import-school-curricula.py
tests/course-planner-data.test.cjs
tests/course-planner-engine.test.cjs
tests/browser-course-planner-check.cjs
```

위 파일 구성은 구현 단계의 제안이며 이번에는 서비스 파일을 만들지 않는다.

기존 탐색관의 과목·학과를 활용하는 최소 공통 색인을 오프라인으로 생성한다. 원본 HTML의 JSON이나 검색/진단 코드는 변경하지 않는다. 탐색관에 추천 페이지 링크를 넣을 때는 `scripts/integrate-curriculum.cjs`에도 반영해 재생성 시 링크가 없어지지 않게 한다.

웹 서버 없이 열던 기존 페이지는 유지한다. 새 추천 도구는 JSON 로딩과 Worker가 있어 로컬 검수는 HTTP 서버를 기준으로 한다. 저장 데이터에는 자료 버전·입학연도를 포함해 데이터 갱신 시 재검토 안내를 한다. URL에 이름·연락처를 넣지 않는다.

첫 버전에는 사용자 계정·백엔드·유료 AI API·자동 상담 전송을 추가하지 않는다. 자유 입력은 안전하게 텍스트로 표시하고 저장 복원 시 스키마·학교·연도·과목 ID를 검증한다.

### 배포 파일 주의

현재 `.vercelignore`가 `!curriculum`으로 폴더 전체를 허용한다. 이 폴더에 원본 엑셀이 새로 들어왔으므로 **다음 배포 전 서비스 HTML/JS/검수된 JSON만 포함되도록 배포 허용 범위를 좁히는 작업**을 먼저 한다. 원본 엑셀을 공개할지는 사용자가 별도로 결정하며 기본적으로 배포하지 않는다. 이번 계획 작업에서 배포 설정 자체는 바꾸지 않는다.

## 9. 개발 순서와 완료 기준

| 단계 | 작업 | 다음 단계로 넘어가는 기준 |
|---|---|---|
| 1. 원본 정리·검수 | 엑셀→정규화 JSON, 코호트 분리, 출처·선택군·표기 매칭 | 3개교 2027 입학생의 345개 편성 행 대조, 미확인 목록과 선택군 규칙 검수 |
| 2. 과목 확인 화면 | 학교·입학연도 선택, 학기별 전체 후보·자료 상태 표시 | 원본 셀까지 추적 가능, 광동고 미확보 표시, 두 시트 혼합 없음 |
| 3. 추천 엔진 | 목표 매핑, 고정 과목, 전 학기 조합 탐색, 이유·대안 | 선택 수·학점·연계 조건을 어기는 안은 결과에 포함되지 않음 |
| 4. 학생 화면 | 단계 입력, 6학기 카드, 과목 교체·재계산·저장·인쇄 | 입력 변경·복원·대안 전환 시 화면과 계산이 일치 |
| 5. 사례 검수 | 실제 자료에 기반한 목표별 시나리오를 학원에서 검토 | 과목·학기·학점·근거 검수 및 오해를 부르는 표현 제거 |
| 6. 기존 사이트 연결·검증 | 탐색관·중고등 메뉴 연결, 모바일·뒤로가기·SEO·배포 목록 | 기존 회귀 검사와 신규 테스트 통과, 원본 엑셀 배포 제외 확인 |

## 10. 반드시 검증할 사례

1. 같은 ‘경영학과’라도 진접고의 선택 확률과 통계와 오남고·진건고의 지정 확률과 통계를 다르게 처리.
2. 진접고에서 편제표에 없는 인공지능 수학을 수강 계획에 넣지 않음.
3. 2027 입학생 자료와 2025 입학생의 고3 편성을 섞지 않음.
4. 광동고 2027 입학생을 고르면 자료 미확보가 표시되고 확정 6학기 추천이 생성되지 않음.
5. 택1·택3·택4·택5의 초과/미달 선택, 그룹 학점 오류, 학년 간 중복·선이수 충돌 감지.
6. 교차 편성 과목을 두 학기에 중복 수강시키거나 확정 시간표처럼 배치하지 않음.
7. 진접고 고3 후보 수와 진건고 고2·고3 후보 수가 입학연도에 따라 달라짐을 보존.
8. 보조 출처 단독·학점 미상·과목명 미연결을 누락/0학점으로 숨기지 않음.
9. 학생 고정 과목 때문에 해가 없을 때 충돌 원인·조정 대안 표시.
10. 희망학과 미매칭·복수 후보·빈 입력·전공 미정에서도 허위 매핑 없이 이용 가능.
11. 2027 입학생에게 2028 대학 권장과목을 현행 요건으로 적용하지 않음.
12. 저장 후 자료 버전이 바뀌면 예전 계획을 그대로 유효 판정하지 않음.
13. 360/390/768/1280/1920px, 키보드 입력, 상세→뒤로가기, 저장 차단·인쇄·오류 복원.
14. 원본 엑셀 SHA-256 불변, 원본 데이터·기존 탐색 기능·상담 동선 보존.

정적/엔진 검사는 Node 기본 테스트로 하고 브라우저 검사는 실제 실행 결과만 PASS로 기록한다. 원본 엑셀의 수식 캐시를 읽은 것을 Excel 재계산 검증이라고 표현하지 않는다.

## 11. 첫 버전 범위와 후속 확장

**첫 버전:** 3개교 2027 입학생, 전 교과 후보 표시, 검수한 진로·학과의 6학기 계획, 선택군 제약·이유·대안, 학생 수정·브라우저 저장·인쇄. 광동고는 자료 확보 현황과 기존 자료 참고만 제공한다. 진로 매핑은 비교표의 자연·공학, 의약·생명, 정보·AI, 상경, 인문·사회·교육 묶음을 출발점으로 하고 기존 탐색관 학과별 연결을 검수해 확장한다.

**후속:** 광동고 2026·2027 편제표, 재학생 입학연도별 전체 편제표, 대학·모집연도별 공식 권장과목, 공동교육과정의 실제 개설 자료, 학교 간 비교, 다중 전공 계획 비교. 학생별 성적 기반 난도 조절·AI 대화는 별도 근거·요구가 마련된 뒤 검토한다.

학생이 ‘수강신청’을 클릭해 학교에 접수하는 기능, 실제 시간표 충돌 보장, 졸업·합격 보장, 임의 대학 적합도 점수는 범위에 넣지 않는다.

## 15. 사용자 후속 승인: 수집 자료로 6학기 추천 진행

자료 수집 다음 요청에서 사용자가 수집 자료로 2027 입학생의 완성 수강 추천을 진행하도록 지시했다. 추천 미지원 제약을 해제하고, `projected` 상태의 추정 추천을 구현한다. 학교 공식 확인을 요구하며 구현을 중단하지 않는다.

- [x] 캡처 60행 + 추가 관측 4행 + 3학년 두 학기 70행 = 과목 후보 134행. 날짜·반 수·원본 이름·관측 연도와 원본 해시 유지.
- [x] 6학기 전체 추천과 조정·대안·저장·복사·인쇄. 선택군은 학교 제약으로 추정하지 않고 ‘서비스 추천 구성’으로 분리.
- [x] 학점 null과 학교 선택 조건 미확인, 3학년 2015 교육과정 참고 안내를 화면·내보내기에 보존.
- [x] 119개 학과 + 전공 미정, 6학기 생성·근거·제외/고정·과거 미입력·다른 학교 회귀 검증.
- [ ] 추후 공식 편제표로 관측·추정 데이터를 교체하고 학점·선택군을 검증.

교과별 기본 추천 개수는 수학·사회·과학 2개, 나머지 1개(후보가 적으면 후보 수까지)다. 이는 탐색을 위한 서비스 구성으로, 전체 수강신청·졸업 이수량을 뜻하지 않는다. 재학생 과목명이 두 학기에 나타나면 그대로 참고하되 중복 학점으로 합산하지 않는다.
